# AI 전략 후보 시뮬레이션

## 목적

서버가 생성한 실행 가능한 전략 후보를 동일한 재고·수요예측 기준으로 평가해
LLM이 비교할 수 있는 요약 지표를 만든다. 동일한 계산 엔진은 추후 LLM이
상세값을 구성한 최종 3~4개 후보의 일별 시계열 생성에도 재사용한다.

## 현재 계산 규칙

- 결과 수량과 손익은 전략 생성 요청의 `evaluationInventory` 범위만 집계한다.
- 식품은 소비기한 우선 FEFO, 소비기한이 없는 상품은 입고일 우선 FIFO를 적용한다.
- 소비기한 당일까지 판매할 수 있고 다음 날 남은 수량을 폐기로 처리한다.
- 실제 판매 가능 기간은 LOT의 `saleStopDate`를 우선 적용하며 판매중지일
  당일부터 판매할 수 없다. 판매중지된 잔여 수량은 자동 폐기로 처리하지 않는다.
- 공용 미할당 재고는 같은 창고 안에서 특정 판매처에 수량을 할당하는
  `REALLOCATION` 후보만 생성한다.
- 전략 적용 수량은 낱개 단위의 정수로 생성한다. ML 예측과 시뮬레이션의
  기대 수량은 계산 정밀도를 보존하기 위해 소수 수량을 유지한다.
- 단독 `REALLOCATION`, `RT_TRANSFER`는 종료일이 없으며 이동 결과는 예측 종료일까지 유지한다.
- 할인은 후보 종료일까지 적용하고 다음 날부터 현재 판매가로 복귀한다.
- 채널 확대 노출은 후보 종료일까지 유지한다. 종료 후 재고 위치는 유지하지만 확대 채널 판매는 중단한다.
- 채널 집중 종료 후에도 기존 입점 판매처의 정상 판매는 계속된다.
- 할인 수요 증가 배수와 RT 이동비는 현재 계산에서 제외하고 후보 가정에 기록한다.
- 순효과는 `전략 공헌이익 - 무전략 공헌이익 - 전략 실행 비용`으로 계산한다.
- 보관비와 폐기비는 순효과에 합산하지 않고 잔여·폐기 수량으로 비교한다.
- 예상 소진 기간은 전략 적용 수량이 전부 **판매**된 경우에만 계산한다. 전략 적용
  수량 중 일부라도 폐기되면 판매를 통한 완전 소진이 아니므로 `null`로 반환한다.

## 출력 수준

- `SUMMARY_ONLY`: LLM 호출 전 전체 후보에 사용하며 요약과 무전략 비교값만 생성한다.
- `WITH_DAILY_SERIES`: 최종 선택 후보에 사용하며 동일한 계산에 일별 재고·매출·공헌이익 시계열을 추가한다.

## 후속 결정: 미래 전략 대상 재고 예약 시점

### 현재 구현

후보의 LOT별 적용 수량은 계산 시점부터 전략 시작일까지 예약된 것으로 가정한다.
예약 수량은 시작 전 일반 판매에서 제외하며, 전략 시작 전에 소비기한이 지나거나
판매중지일에 도달하면 해당 후보를 제외한다. 미래 시작 후보의 결과에는
`INVENTORY_RESERVED_UNTIL_STRATEGY_START` 가정을 기록한다.

### 미확정 이유

- 실제 시스템이 전략 승인 전에 재고를 예약할 수 있는지 확정되지 않았다.
- 생성 즉시 예약하면 정상 판매 기회를 제한할 수 있다.
- 예약하지 않으면 시작일까지 재고가 판매되어 추천 수량을 실행하지 못할 수 있다.
- 생성, 승인 요청, 승인 완료, 실제 실행 중 어느 시점에 예약할지 승인 흐름과 함께 정해야 한다.

### 팀 검토 대안

1. 전략 생성 시점부터 전량 예약
2. 사용자가 최종 전략을 선택한 시점부터 예약
3. Teams 승인 완료 시점부터 예약
4. 예약하지 않고 실행 직전에 재고를 재검증
5. 예상 사전 판매량을 반영해 일부 수량만 예약

정책이 변경되면 후보 생성 시점의 실행 가능 수량, 시뮬레이션의 시작 전 판매,
실행 직전 재검증 및 실패 처리 규칙을 함께 수정해야 한다.
